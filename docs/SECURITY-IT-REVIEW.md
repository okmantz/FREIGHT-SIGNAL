# Notes for IT / security review

* **Static site only.** No server component of its own. **Optional (v9):** cloud accounts through a Firebase project owned by the site owner (Authentication + Realtime Database, REST over HTTPS, no SDK). Off unless `js/config.js` is filled in. When on, each person's workspace (loads, carrier and customer e-mail addresses, rates, settings) is stored in that project under `users/<id>/`, readable only by that signed-in person (rule in `database.rules.json`); the project owner can view it in the Firebase console; it is not end-to-end encrypted. Confirm company policy allows this before using real data.
* **No network use at runtime** except loading the app's own files from the host, the cloud-account calls above (only when switched on: `identitytoolkit.googleapis.com`, `securetoken.googleapis.com`, `*.firebaseio.com` / `*.firebasedatabase.app`), plus ONE optional call: US National Weather Service alerts (`https://api.weather.gov`). Only a city's latitude/longitude is sent, never load, customer, carrier or rate data. It can be turned off in System → Weather. No CDN, fonts, analytics or telemetry. CSP (`connect-src 'self' https://api.weather.gov`; single-file build: `connect-src https://api.weather.gov`) enforces it; an e2e test fails if any other request leaves the origin.
* **Outlook macro v5 never sends mail.** It only saves drafts (`.Save`) from `freight-signal-outbox.tsv`, and only when Outlook is touched (activate/select, new mail, startup or `FS_DraftsNow`).
* **No secrets** in the repository. Blocklists ship empty and are entered at runtime.
* **No Outlook/Exchange/Graph access from the app, no COM, no credentials.** The app cannot read or send mail. Outlook is touched only when *the user* opens a downloaded `.eml` or clicks a `mailto:` / OWA link.
* **Outlook bridge (optional):** if the user chooses a folder (File System Access API, per-folder permission prompt), the app writes plain-text feeds there (postings, rate rules, blocklist) and reads Outlook's event log. The Outlook macro (`outlook/Outlook_v5_ThisOutlookSession.txt`) is user-installed VBA that only reads/appends those files and creates unsent drafts; it makes no network calls and sends nothing. The folder permission can be revoked any time (System → Disconnect).
* **XSS:** UI is built with DOM text nodes (no `innerHTML`); CSP forbids inline script in the hosted build and allows only hashed scripts in the single file. An e2e test injects `<img onerror>` into data and verifies it stays inert.
* **Outbound links** (`iq.dat.com`, `ventusky.com`, `outlook.office.com`) open in a new tab with `noopener,noreferrer`; no company data is put in those URLs except lane text for RateView (city/state/equipment) and, for OWA, the draft the user clicked.
* **Third-party data:** `data/uszips.csv` (licence to be confirmed). Dev-only deps: `playwright`, `esbuild`. No runtime dependencies.
* **Bypassing controls:** nothing in the app attempts to. The `.eml`/`mailto:` route is the standard supported way to create unsent drafts.
* **Data at rest** is unencrypted browser storage, like any web app on that profile; rely on disk encryption / profile controls.
